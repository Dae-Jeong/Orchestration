전체 업무 · 역할 내부 작업 · 인계와 검증

제품 실행과 마케팅, 공통 HR 리뷰를 한 캔버스로 펼쳤습니다. 역할과 모델 배정은 운영안이며, 상시 실행 중인 agent 구성이 아닙니다.

QA는 최초 기준 설계부터 참여합니다. 결함은 해당 역할로 돌아가고, 범위·기준·권한 변경은 PM이 조율합니다. 역할 간 모든 양방향 인계 조건은 아래 표에 이어집니다.

Astra / Sol 후보

QA / reviewer

검증자·모델 미정
  1. 초기 기준·검증법 설계
  2. revision/hash 대조
  3. 정상·예외·회귀 재현
  4. 기준별 판정·증거

받는 것 기획 기준, 디자인 상태/화면, 개발 변경/재현 → PM에 pass/fail/unknown, 검증자와 근거. 자가 검증은 독립 검증으로 부르지 않음.

막히면 기준 모호성은 기획·PM, 시각/원본 문제는 디자인, 코드 결함은 개발. 재현 불가는 unknown으로 남기고 필요한 자료를 요청.

마케팅

모델 미정
  1. 제품·고객 근거
  2. 포지셔닝·메시지
  3. 채널·실험·측정
  4. 제작·실행 인계
  5. 성과·한계·후속

받는 것 PM의 제품 맥락·성과·허용 범위 → PM·디자인·개발에 제작 요구, QA에 측정 정의, HR에 실행·성과 근거.

완료 산출물·측정 확인과 제품 성과를 분리. 데이터 부족은 unknown, 메시지/타깃 가설은 재검토. 게시·광고·연락은 승인된 효과 내에서만 실행.

HR / agent 운영

모델 미정
  1. 역할·도구 준비
  2. 수행 근거 수집
  3. 직무별 공동 리뷰
  4. 개선 작업 제안
  5. 후속 효과 확인

받는 것 모든 역할의 진행·판정·증거·환경/버전 → PM에 원인 가설·개선안·검증법. 전문 판정은 QA·해당 역할과 함께하며 HR이 단독 채점하지 않음.

완료 근거·비교 조건·미지값과 다음 검토 조건이 명시됨. 근거 부족은 수집 요청, 판정 충돌은 PM/사용자. HR 개선 효과도 PM/사용자가 검토.

역할 간 인계·피드백 계약 ↑ 전체 흐름

역할 간 전문 질문은 직접 주고받을 수 있습니다. 작업 범위·기준·우선순위의 변경과 재배정은 PM이 조율하고 업무 기록에 남깁니다.

역할 성과와 HR 리뷰

제품 성과·산출물 품질·실행 효율을 분리합니다. 지표 정의/분모·관찰 기간·표본·근거·reviewer를 기록하고, 누락은 unknown으로 둡니다. 기획 누락·디자인 인계·회귀 결함·측정 품질·준비 실패 등은 역할별 개선 후보이며 목표치는 미정입니다. 지표 후보·측정 계약·조사 근거

주기 점검 루프 · 아직 제안

깨움 → 변경 확인 → PM 판단 → 범위 안 실행/대기 → 검증·기록 → 다음 깨움. 새 일이 없으면 실행 없이 종료하고, 활성 시도가 있으면 중복 시작하지 않습니다. 이벤트 반응에 주기적 누락 점검을 보태는 방식이 후보입니다. 대상·주기·비용/시간 한도를 정하기 전에는 반복 실행을 켜지 않습니다.

작게 시작하는 실행 단위

총괄 1 + 필요한 실행자 + 검증자로 시작합니다. PM·기획을 한 세션이 맡을 수 있고, 디자인이 필요 없는 작업은 개발로 바로 보냅니다. 작성자와 검증자가 같으면 독립 검증으로 포장하지 않습니다.

모델을 바꿔도 task ID·기준·권한·증거와 인계 계약은 유지합니다. 실제 모델 배정은 작업의 난도·도구 접근·한도·검증 결과를 보고 확정합니다.

실제 설정은 어디까지인가

Paperclip의 Design Readiness는 codex_local / paused이며 모델명이 고정되지 않았습니다. 전용 home도 호스트 기본 모델을 명시적으로 복사하지 않아, Astra로 실행된다고 단정할 수 없습니다.

Pencil 연결은 성공, UIBowl은 인증 401입니다. Paperclip 상시 역할 agent와 자동 역할 배정은 미구성입니다. Orca 단발 QA·HR 실행은 첫 실제 시범 기록에서 별도로 확인합니다.
