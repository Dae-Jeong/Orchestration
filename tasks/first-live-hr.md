## 범위·근거·착수 조건

표본은 README 정합성을 다룬 **문서 작업 1개**다. PM 편집 → 별도 QA → 이번 HR
리뷰의 실제 근거만 검토했다. 이 보고서만 작성했으며 테스트·이미지 검증을 재수행하거나
Paperclip을 직접 조회하지 않았다. 역할 전문 품질을 단독 채점하는 리뷰가 아니다.

- [시범 계약·실행 기록](first-live-pilot.md): 권한, 기준, 한도, 시작 장애와 재시도.
- [독립 QA 보고서](first-live-qa.md): C1–C3 판정, 명령 결과, 산출물 hash, 비차단 개선과 한계.
- [성과 측정 운영안](../docs/role-performance.md), [역할 계약](../skills/squad-model/references/roles.md): 해석·인계 기준. 제도가 시행되거나 효과가 입증됐다는 근거로 쓰지 않았다.
- coordinator의 이번 Orca 회신: authoritative QA 성공 settlement 수신, C1–C3 직접 검토,
  ORC-8 done 반영 후 HR 착수 조건 충족을 확인했다. 이는 coordinator 확인 근거이며
  HR의 독립 API/receipt 검증은 아니다. 최초 열람 때 남아 있던 QA 미완료 체크도 갱신했다고 답했다.

관찰 기간은 2026-09-10의 이번 bounded pilot, HR은 10분 한도 내 1회 문서 리뷰다.
시범 기록에 Codex 0.153.4와 QA worker projection의 gpt-6-astra가 명시되어 있으나
HR이 설정을 재검증하지 않았다. HR의 실제 모델 식별값과 skill 버전은 별도 측정하지 않았다.

## 원인 가설과 개선 제안 — 최대 2개

아래는 PM이 채택 여부를 판단할 **제안**이다. 이번 HR이 운영 절차를 변경하거나 정기
리뷰·자동화를 활성화하지 않았다. 기준선은 위 단일 사례이며 목표 비율·비교군은 없다.

| 개선 제안 | 관찰 → 원인 가설 | 담당·범위 | 관찰 가능한 검증·다음 검토 조건 | 미지값·한계 |
| --- | --- | --- | --- | --- |
| 1. 다음 승인된 단발 실행에서도 입력 전 준비 확인을 명시적으로 남긴다 | 업데이트 UI로 시작 전 실패 후 준비 확인을 거쳐 재시도했다. **가설:** 입력 가능한 상태 확인이 dispatch에 일관되게 연결되지 않으면 같은 대기가 재발할 수 있다. UI가 나타난 이유나 기존 확인 누락은 입증하지 못했다. | PM/coordinator가 다음 유사 문서 QA 1회에 적용 여부 결정. 준비 확인 결과와 입력/실행 시작 여부를 구분해 기존 task 증거에 남기고, 실패 시 환경 사건과 수행 실패를 분리한다. 이번에 사용한 동일 task 재시도 이력을 보존한다. | 다음 실행에서 준비 확인 → 입력 → 실행 시작의 순서 및 시작 전 장애 유무를 PM이 확인하고 HR이 검토한다. 재발하면 환경 원인과 준비 확인 방식부터 재검토한다. | 이번 복구는 이미 관찰됐지만 절차의 반복 효과는 미검증이다. 다음 1회 성공도 인과 효과나 안정적 성공률을 입증하지 않는다. 모델 교체·업데이트 정책 변경은 제안 범위 밖이다. |

QA는 독립 재검증이 배정될 때만 담당한다. | PM은 수정한 라벨의 Paperclip/Orca 범위, HTML의 단발/상시 구분, 재생성 PNG의 실제 안내·링크를 확인하고 수정 후 파일과 증거를 연결한다. 기존 QA hash와 구분해 PM 자가 검증으로 표시한다. 다음 인계에서 상태 불일치로 인한 확인 질문 여부를 관찰한다. | 이 보고서 작성 시 수정 완료·검증 결과는 확인하지 않았다. 3건은 비차단이며 독자 오해의 실측은 없다. 기록 일치나 표현 수정만으로 제품 이해도 개선을 주장할 수 없다. |

## QA 판정이 HR·다음 작업에 미치는 조건

이번 HR 착수는 QA 문서 존재만으로 해제하지 않았다. coordinator가 authoritative settlement,
C1–C3 판정 검토와 선행 상태 반영을 확인한 뒤 리뷰를 진행했다. QA의 C4 unknown은 담당
범위 밖이라는 뜻이고 C5 unknown은 후속 리뷰 전이라는 뜻이므로 QA 실패로 합산하지 않는다.
동시에 두 unknown을 전체 계약 pass로 자동 전환해서도 안 된다.

비차단 3건은 HR을 막지 않으며 PM이 채택·보류를 결정한다. 수정되면 기존 독립 QA 판정은
수정 전 기준점에 보존하고, PM 자가 검증을 새 독립 QA처럼 표시하지 않는다. 필수 조건에
영향을 주는 변경·fail·재현 불가 unknown이 생기면 해당 후속 완료를 보류하고 담당 수정 또는
QA 재검증으로 돌린다. 기준 변경 시 revision/hash와 증거 적합성을 다시 확인하며 계약의
수정 재검증 최대 1회 한도를 넘는 판단은 PM에 돌린다.
