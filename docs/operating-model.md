# 운영 모델

역할·모델 배정과 업무 프로세스의 개요입니다. 구체 계약의 정본은
[Squad Model skill](../skills/squad-model/SKILL.md)에 있습니다.

## 역할과 모델

| 역할 | 맡는 일과 내부 흐름 | 다음 인계 | 모델 배정 후보 |
| --- | --- | --- | --- |
| 사용자 · 대표 | 제품 방향·목표·허용 효과 결정, 위임 밖 판단 | PM에 소재·목표·권한 | 사용자 |
| PM / coordinator | 원문 근거 → 문제·우선순위·범위 → 기준 합의 → 역할 배정 → 진행·후속 판단 | 역할별 계약·시작 조건, 사용자에게 결과·판단 요청 | Astra |
| 기획 | 시나리오 → 업무 규칙 → 상태·예외·복구 → QA와 수용 조건 | 디자인에 플로우, 개발에 규칙, QA에 기준 | Astra / Sol |
| 디자인 | 컨셉 → 레퍼런스 → 시안·피드백 → 토큰·컴포넌트·렌더 검토 | 개발·QA에 원본/버전·노드·상태·토큰 매핑·화면 증거 | Astra / Sol |
| 개발 | 선행 산출물 확인 → 기존 코드 재사용 → 구현 → 테스트·브라우저 검증 | QA에 변경·재현 절차·증거, 리뷰 가능한 PR 제안 | Terra / Sol |
| QA / reviewer | 초기 기준·검증법 설계 → 기준 revision/hash 확인 → 재현 → pass/fail/unknown | PM에 판정·증거, 해당 역할에 결함·재검증 요청 | 별도 검증자, 모델 미정 |

역할마다 별도 agent를 항상 띄우지는 않습니다. 작업에 필요한 역할을 배정하며,
작성자가 스스로 검증한 경우에는 자가 검증으로 표시합니다.
구체적인 입력·권한·시작/완료 조건·실패 귀환은 [역할 계약](../skills/squad-model/references/roles.md)에 있습니다.

## 업무 프로세스

1. **소재 수집:** 사용자 행동·리서치·이전 실험의 원문에서 시작하고 관찰·해석·가설을 구분합니다.
2. **PM 조율:** 문제·대상 사용자·성과 지표·우선순위·범위와 비범위를 정리합니다.
3. **작업 계약:** 기획·QA와 관찰 가능한 완료 조건, 검증법·증거·reviewer, 허용 효과와 한도를 맞춥니다. 이미 허용된 범위는 반복 승인하지 않습니다.
4. **배정·착수:** 선행 검증 완료와 공유 파일·DB·디자인 원본의 쓰기 충돌을 확인합니다. 준비된 작업은 병렬 진행하고, 나머지는 대기 이유를 기록합니다.
5. **역할 실행·인계:** 각 역할이 상세 작업을 관리하고 산출물·질문·남은 일을 인계합니다. 규칙 모순은 기획, 원본·매핑 누락은 디자인, 구현 결함은 개발로 돌아갑니다.
6. **검증·수정:** QA가 합의된 기준별로 판정하고 PM이 완료·수정·대기를 결정합니다. 기준 변경·새 권한·한도 소진은 필요한 사람 판단으로 연결합니다.
7. **후속·학습:** 검증된 완료가 후속 작업을 해제합니다. 실제 제품 성과는 별도로 관찰하고 성공·실패·무효 결과와 한계를 다음 소재에 반영합니다.

`task_id`는 안정적으로 유지하고 기준 `revision`·`hash`와 `depends_on`은 별도로 관리합니다.
기준이 바뀌면 영향 범위와 이전 증거의 유효성을 다시 확인합니다. 실패·검토 중인 작업은 완료로 취급하지 않습니다.

## 여러 제품과 실행 도구

공통 오케스트레이션 아래 제품별 프로젝트와 작업 맥락을 구분하는 운영안입니다.
PM은 제품 간 우선순위·공유 자원을 조율하고, 실행자는 해당 제품의 repo·workspace에서 작업합니다.
프로젝트 간 자동 실행은 아직 검증하지 않았습니다.

| 구분 | 책임 |
| --- | --- |
| 프레임워크·작업 계약 | PM의 판단, 역할별 책임, 완료 기준·권한·인계 규약 |
| Paperclip | 검증 가능한 업무 단위의 담당·상태·blocker·review·증거 기록 |
| Orca | 현재 연결안의 제품별 workspace·worker 배치와 실행 시도 조율 |
| 제품 repo | 역할이 관리하는 상세 체크리스트·설계 원본·코드·검증 산출물 |

PM이 도구를 호출해 조율하며, 업무 계약은 도구와 분리합니다. 별도 scheduler는 추가하지 않습니다.
이벤트 반응에 주기적 누락 점검을 보태는 [루프 운영안](../skills/squad-model/references/review-loop.md)은
주기·비용·시간·재시도 한도가 미정이며 미활성 상태입니다.
